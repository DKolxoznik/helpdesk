# Отчёт по практике

Тема: сервис обработки заявок на Java и Kotlin.

## Что сделано

- Спецификация: 8 историй, критерии приёмки, функциональные и нефункциональные требования.
- Модель процесса, ER-диаграмма, контракт API и backlog на 72 часа.
- REST API заявок и категорий на Java, PostgreSQL, миграции Flyway, история статусов в одной транзакции.
- Сводка `GET /api/reports/summary` на Kotlin. Java-контроллер вызывает Kotlin-сервис, сервис читает данные через Java-интерфейс.
- 48 автотестов, в том числе PostgreSQL через Testcontainers, два сквозных сценария и регрессия DEF-001.
- Docker Compose, health check, резервная копия и восстановление в отдельную базу.
- GitHub Actions: проверка форматирования, тесты, отчёты, публикация образа по SHA и запуск на стенде. Для pull request развёртывания нет. Откат описан workflow `rollback`.

## Как Kotlin повлиял на код

Сводка возвращает `ReportSummary`, это data class. Среднее время имеет тип `Double?`. Для пустого списка длительностей используется `takeIf { it.isNotEmpty() }?.average()`, поэтому отсутствие завершённых заявок остаётся `null`. Ноль секунд и «посчитать нечего» не смешиваются. Подсчёты статусов, приоритетов и просрочки сделаны операциями `filter`, `count`, `mapNotNull` и `associateWith` по одному списку, который сервис получил от Java.

На границе языков Java-записи `TicketSnapshot` приходят с платформенными типами. Сразу после выборки они превращаются в Kotlin-класс `MeasuredTicket`, где `dueAt` и `closedAt` уже `Instant?`. Дальше `closedAt?.let` обязателен: заявка `RESOLVED` без времени закрытия не попадает в среднее и не роняет расчёт. Компилятор Kotlin собран с `-Xjsr305=strict`, чтобы аннотация `@Nullable` на Java-полях была видна. Вызов устроен так: `ReportController` на Java получает `ReportService` на Kotlin, а тот зависит только от Java-интерфейса `TicketReportSource`.

## Дефект

DEF-001: проверка редактирования сначала запрещала только `CANCELLED`, и завершённую заявку можно было изменить. Регрессионный тест поймал это сообщением `Expected TicketNotEditableException to be thrown, but nothing was thrown`. Исправление — общий запрет для конечных статусов. Подробности в [defects.md](defects.md).

## Ограничения

- Нет аутентификации и разделения ролей. Это было за границей задания.
- Нет графического интерфейса. Проверка идёт через Swagger и коллекцию HTTP.
- Учебный стенд pipeline поднимается на runner GitHub Actions и после smoke-проверки останавливается. Постоянный том и откат образа на своей машине описаны в инструкции. Если преподаватель даст отдельную виртуальную машину, на неё ставится тот же Compose и образ `ghcr.io/dkolxoznik/helpdesk:<sha>`.
- Среднее время — среднее арифметическое секунд между созданием и закрытием заявок `RESOLVED`.
